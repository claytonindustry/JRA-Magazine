Putting the names back

We know a browser will not honour translate="no" on a phrase inside a paragraph. But a browser does not rebuild the paragraph when it translates it — it keeps the elements and swaps the words inside them. So the name's own little box should still be there afterwards, holding French. If it is, a few lines of script can simply put the English back, and nothing needs translating by hand at all.

How to run it
  1. Right-click the page, Translate to French. Then do it again in Chinese.
  2. Every paragraph should turn French. Look at the three yacht names in each: Mirror, Shining Moon and Great Auk.
  3. Tell me, for each numbered paragraph, whether those three names are still in English — and whether anything flickers, jumps or repeats.
  4. The counter at the bottom says how many times the script put a name back. If it climbs for ever, the script and the translator are fighting and that matters as much as the result.

What each answer would mean

If 3 or 4 keeps its names — this is the answer. Readers translate the page themselves, boat names stay as written, and there is no manual translation of anything, ever. I would put it in the published page and we would be done.

If they keep them but the counter climbs without stopping — it works but fights the translator. Fixable, probably by giving up after a few goes, but I would want to see how bad it is.

If 3 and 4 fail the same way 2 does — the browser is rebuilding the paragraph rather than filling it in, there is nothing left to put back, and manual translation stays the only way to keep a name.

5 is the control and should stay wholly English in both languages. 1 should translate completely, names and all.
